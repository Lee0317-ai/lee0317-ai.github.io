## 它解决什么问题

中文长篇小说的 AI 辅助写作，常见两个极端：

1. **AI 一把梭**：让模型一口气写完整本书，结果是开头惊艳、三章后设定崩塌、人物 OOC、伏笔丢失；
2. **AI 只当润色**：只用 AI 改语句，那它对结构、人物弧光、世界观一致性毫无帮助。

NovelVerse 走的是中间路：**把写作拆成可追溯的创作链——作品 DNA → 角色与世界 → 卷纲 → 章卡 → 正文 → 监督 → 锁定 → 记忆沉淀**。AI 在每一环都只产出"候选草稿"，由作者确认后才写入正史；作者的每一次手写、修改、回滚也都进版本。这样长篇写到第 30 章时，第 5 章埋下的伏笔仍然能被记住、被校验、被兑现。

## 技术实现

### 三种写作模式

- **短篇**：有明确篇幅和结尾；默认可直接从作品总纲跳到首章章卡；
- **架构师**：长篇或强结构；按"作品总纲 → 当前卷纲 → 章卡 → 正文"推进，只要求准备当前卷和下一章，不要求拆完所有卷；
- **园丁**：先写场景与人物，后由系统回填章卡与卷纲草稿，再由作者确认。

模式只影响默认引导顺序，不限制手写、AI 对话或切换模式。

### 创作链与可追溯性

- **章卡**：系统根据总纲、当前卷、已锁定事实、上一章收束和本次要求生成草稿；作者可手改、可让 AI 重做、补强冲突或调整节奏；确认后才进入正文；
- **正文**：手写自动保存 + 离页保护 + 本地未保存恢复；AI 结果以工作草稿/变体呈现，不静默覆盖；
- **监督**：连续性、事实冲突、风险交给作者审阅；锁定前可继续改；
- **锁定**：沉淀章节摘要、角色状态、伏笔、时间线与其他故事事实；
- **分支与版本**：从任意章节创建分支、比较差异、回滚或归档，不破坏主线；
- **记忆中心**：查看正史、角色/物品/势力状态、时间线与待裁决冲突。

### 角色 Agent 的三级决策

角色不被 AI 直接驱动，而是分级：

- **绿**：低影响（日常行为、对白），Agent 可自主；
- **黄**：中影响（关系推进、小决策），Agent 给建议，作者采纳与否；
- **红**：高影响（死亡、重大关系转折、核心秘密揭露），必须作者显式确认。

### 底层栈

- **Core**：Python 3.12 + FastAPI + SQLAlchemy 2 + Alembic；
- **数据库**：PostgreSQL 18 + pgvector（长篇记忆向量检索）；桌面版内嵌私有 PostgreSQL，不监听 TCP；
- **前端**：React 19 + Vite + TipTap 富文本编辑器；
- **桌面**：Tauri 2（Rust），macOS DMG 发行，应用启动时拉起私有 Core 与数据库；
- **模型接入**：OpenAI-compatible 与 Anthropic 双协议，密钥存系统凭据库（keyring），不写进作品或备份；
- **Prompt 工程**：每个任务的 Prompt 都有版本管理，支持按功能分配默认模型、单次临时切换，并记录用量与费用。

### 隐私边界

- 不配模型也能完整手写、自动保存、离页保护、锁章、恢复、导出 Markdown/TXT；
- AI 共创、生成、审稿功能在没有可用模型时自动禁用；
- 密钥走系统凭据库；作品、数据库导出、备份中不含 API Key；
- 桌面版数据库只绑定 localhost 不监听外部 TCP。

## 当前状态

**状态：进行中（wip）。** Web 工作台可直接开发模式运行，macOS DMG 已能打包；本机库中已有 23 部测试作品持续使用，验证了作品库、构思工作流、章卡/正文编辑、锁定与记忆沉淀的主流程。

已实现的完整能力清单（与 README 对齐）：

- 中文小说初始化、章节规划、生成、修订、监督与锁定；
- 作品 DNA、角色、世界观、情节蓝图与定名的可恢复构思资产；
- 构思确认后原子创建正式作品并按蓝图章节数初始化；
- 无模型手写、自动保存、离页保护、本地恢复与草稿导出；
- 短篇、架构师、园丁三种写作模式；
- 角色自主决策与绿/黄/红三级确认规则；
- 章节回滚、活动分支切换、历史归档；
- 章节摘要、角色状态、伏笔、时间线记忆；
- OpenAI-compatible 与 Anthropic 模型调用、按功能默认模型与单次临时切换；
- Prompt 版本管理、模型用量与费用记录；
- 长篇记忆回填与 pgvector 向量检索；
- 文件或粘贴文本导入，Markdown/TXT 导出；
- 本地备份、恢复与完整迁移验证。

**设计定稿、尚未实现**的后续方向：

- **汇聚宇宙**：多部作品共享世界观与角色的能力；
- **去 AI 味**：识别并弱化模型生成的常见腔调与套话。

**已知的保守表述**：DMG 发行版在 Apple Silicon 上可正常安装运行；Windows / Linux 桌面版暂未打包。Web 开发模式需要本机已有 PostgreSQL 18 与 pgvector，这是面向开发者的形态，不是面向终端用户的安装包路径。
