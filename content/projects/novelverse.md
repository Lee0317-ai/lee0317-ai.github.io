NovelVerse 是一个本地优先、面向中文小说创作的 AI 写作工作台。它的核心不是让 AI 一次写完一本书，而是把每一步的意图、草稿、确认版本和后续影响放在同一条可追溯的创作链上：章节计划、正文、角色决策、监督报告、记忆和模型调用记录全部存为可追踪的版本。不配置模型也能完整手写、自动保存、锁章、恢复和导出。

## 它解决什么问题

长篇创作的两个老大难：设定崩坏（写着写着忘了伏笔、角色状态漂移）和 AI 代写失控（生成内容静默覆盖作者文本）。NovelVerse 用"记忆层 + 版本快照 + 确认关卡"正面处理这两件事——AI 结果一律以工作草稿/变体出现、由作者挑选采用，已锁定的正文和正史绝不被自动重写。

## 技术实现

- **写作台**：短篇、架构师（总纲 → 卷纲 → 章卡 → 正文）、园丁（先写场景再回填结构）三种模式共享同一套资产；"当前最重要的一步"作为唯一主入口驱动推进，离开时保护现场、异常退出可恢复本地未保存内容。
- **版本与回滚**：每章锁定时保存记忆层快照（摘要 + 角色状态 + 伏笔台账），回滚到第 N 章即加载该快照、其后章节进归档分支保留可对比，不破坏主线；上游设定修改会提示受影响的下游内容，由作者决定同步或保留。
- **角色 Agent**：角色作为带人格档案的 sub-agent 可自主决策，决策按绿/黄/红三级确认（红级如角色生死、主线节点必须执行前确认）；叙事层（作者）优先级高于角色层。
- **长篇记忆**：章节摘要、角色状态、伏笔与时间线入记忆中心，PostgreSQL + pgvector 向量检索支撑超长篇上下文；Prompt 版本管理、模型用量与费用记录。
- **工程形态**：FastAPI Core + React/TypeScript/Vite 前端 + Tauri 2 桌面壳；模型密钥只存系统凭据库（macOS Keychain / Windows Credential Manager），macOS 发行版自带私有 PostgreSQL + pgvector 运行时，无需用户自行装库。

## 当前状态

架构底座与小说创作闭环已实现：中文小说初始化、章节规划、生成、修订、监督与锁定，构思资产（作品 DNA / 角色 / 世界观 / 情节蓝图）逐项确认后原子创建作品，短篇/架构师/园丁三模式、章节回滚与分支、pgvector 记忆检索、Markdown/TXT 导出与备份恢复均可用，配套 P1 统一验证脚本。汇聚宇宙、去 AI 味层等能力已在领域设计文档中定稿，属后续方向。
