通用桌面 Agent 拿来就能用，但真拿它干活会担心两件事：任务说完成就完成、没有证据；高危动作（比如生产部署）说干就干。WOS 基于网易有道开源的 LobsterAI（MIT 协议）深度改编，目标是一个改编可控、验收有据的桌面 Agent 工作台：品牌、数据目录与验收体系完整迁移到 WOS，同时完整保留上游许可与署名。

## 它解决什么问题

fork 一个开源项目容易，让它在自己的场景里"可信任"难。WOS 的改编围绕一条主线：把"Agent 说做完了"变成"证据齐了才算做完"——执行、等待复核、部分完成的状态边界由验收报告单一事实源定义，凡是没验证过的能力一律如实列为未验证，不冒充已完成。

## 技术实现

- **证据定验收**：run 走完 finalize 并集齐必需证据才进入 accepted；缺必需证据停在 partial，失败的证据同样不会被标成 accepted，`run.completed` 不直接等于验收通过。
- **权限与审批边界**：生产部署等高危能力必须 confirm；工作区之外的文件操作直接拒绝。拒绝经真实路由边界返回，不推进 `startSession` / `continueSession`，非法审批响应在路由前被拦截。
- **事件持久化与恢复**：从持久化事件恢复被中断的 run、保持事件顺序，幂等键防止已完成的动作重复执行。
- **数据迁移兼容**：LobsterAI 旧归档根目录在 WOS 品牌下可读可恢复，未知根目录拒绝并保留路径安全检查；新备份写入 WOS 根目录。
- **安全基线**：渲染进程启用上下文隔离、禁用 Node 集成、开启沙箱，渲染层访问主进程只走 preload IPC；应用数据存本地 userData。
- **可选外部 Agent**：Codex / Claude Code 是可选扩展而非运行前提，测试层同时覆盖"有 Codex 用外部 Agent"与"无 Codex 回退原生执行"两条路径。

## 当前状态

P0 验收结论"有条件通过"：固定 P0 回归 270/270、Agent 编排 257/257、数据迁移 20/20 通过，Electron 主进程编译与渲染层构建通过，首页、高级执行选项与 Sidebar"运行中/待复核"投影有真实启动截图佐证。未验证项如实列在验收报告中：真实任务端到端（缺 provider 与运行时）、Windows 安装包、签名与自动更新、Computer Use 与紧急停止、会话页端到端等——这些是进入 P1 前必须补齐的清单。
