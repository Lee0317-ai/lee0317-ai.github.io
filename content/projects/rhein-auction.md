## 它解决什么问题

线上拍卖最要命的不是页面好不好看，而是**出价那一刻的并发正确性**：几百上千人同时出价，
系统必须保证三件事——出价便宜的立刻被驳回并告知原因、同一个拍品永远只有一个赢家（不超卖）、
网络重试不会产生重复出价。传统"查一下当前价再更新"的写法在并发下必然出错。

rhein 拍卖系统把整个出价决策做成了一个 **Redis Lua 原子脚本**：校验与写入在 Redis 内一次性完成，
中间不存在被并发插入的时间窗口。1000+ 人同时竞价，每一次出价的结果都是确定性的。

## 核心技术：Lua 原子出价引擎

一次出价 = 一次 Lua 脚本执行，全部决策在 Redis 内原子完成：

1. **幂等去重**：requestId 查重，24 小时内相同请求直接返回原结果（网络重试不重复出价）
2. **状态与时间校验**：拍品状态是否允许出价、是否已过结束时间，不允许则返回明确原因
3. **价高者得规则**：首次出价须 ≥ 起拍价；后续出价须 ≥ 当前价 + 加价幅度，且必须是加价幅度的
   整数倍——低价出价毫秒级驳回，错误原因中文化返回
4. **延时周期**：出价时间落入延时窗口（如结束前 30 秒）自动顺延结束时间（次数可配），杜绝卡秒抢单
5. **原子写入**：INCR 出价序号 → HSET 最新价 / 最新竞买人 / 出价次数 → LPUSH 出价记录 →
   XADD 事件流（BID_ACCEPTED）→ 返回最新结果，全链条无锁、无竞态

配套设计：金额全链路以"分"（Cent）整数计算规避浮点误差；lotKey 使用 hash tag 保证 Redis Cluster
下同一拍品的键落在同一 slot；出价记录以 Redis Stream 发布，前端实时刷新当前价与竞价倒计时。

## 业务功能

- **竞拍大厅**：拍品按进行中 / 即将开始 / 已完成分组，实时当前价、竞价人数、倒计时
- **竞拍详情**：拍品介绍、当前价、最小涨幅、延时周期、逐笔出价记录（金额递进、竞买人脱敏）
- **业务闭环**：专场管理、拍品管理（含导入与错误重试导出）、竞价记录、成交结果、提货管理，
  审批环节接入 BPM 工作流
- **接口集成与数据脱敏**：与客户自有平台打通注册 / 会员 / 消息链路；生产数据脱敏 runbook
  （备份 → 脱敏 → 校验 → 人工确认 → 回滚预案）
